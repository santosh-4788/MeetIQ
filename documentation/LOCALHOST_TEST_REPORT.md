# OneInsure Connect — Localhost Test Report (browser click-through)

**Date:** 1 November 2026 · **Scope:** Phases 1–3 (sign-in, MFA, masters, administration, settings, meetings, calendar, notifications, dashboard) plus the new "link account to employee" feature. The Phase 4 video room is covered by its own test (`tests/e2e/room/`) and is **not** part of this report's results.

**Method.** Automated click-through in **Microsoft Edge (headless)** through `playwright-core 1.64.1` — suite `tests/e2e/` (how to run: `tests/e2e/README.md`). Every case clicks through the real UI against the real API and a real (local) database. A case is marked **PASS only when the observed result matched the expected result**; a case also fails automatically on any uncaught page error or any HTTP 5xx from `/api/v1` while it runs. Failure screenshots: `tests/e2e/results/screenshots/`. Raw results: `tests/e2e/results/results.json`.

## Test environment (isolated — nothing shared was touched)

| Item | Value |
|---|---|
| Database | `OneInsureVideoMeetingDB_E2E` on `(localdb)\MSSQLLocalDB`, migrations V001–V011 via `database\deploy-database.ps1` |
| API | Debug build on `https://localhost:7190`, Development, `Email__Enabled=false` (all mail stays in `app.EmailOutbox`), raised login/reset rate limits, reminder poll 5 s |
| Web | Vite dev server `http://127.0.0.1:5174`, `--mode api`, proxy → 7190 through the new `OIC_API_TARGET` variable in `frontend/vite.config.ts` |
| Browser | Microsoft Edge headless, 1440×900 and 390×844 viewports, locale en-IN, time zone Asia/Kolkata |
| Not touched | shared SQL Servers, the developer API (7180) and Vite (5173), user secrets, real e-mail |

**Seed** (`tests/e2e/seed.mjs`, through the API, plus SQL only for a meeting in the past): SuperAdmin from `setup-admin` (left **unlinked** to an employee, exactly like a real first install), Admin, HR Master, Employees with employee records, an Employee account without employee record, an account without roles, a Compliance Auditor (created in scenario 02); 5 departments, 3 designations, 2 branches, 1 team; 31 employees (22 through the CSV import API); 2 customers; scheduled, management, draft, cancelled, completed (past) and customer (PLVC) meetings; a leave period.

**Roles exercised:** SuperAdmin · Admin · HR Master · Employee (host and attendee) · Employee account without employee record · account without roles · Compliance Auditor · anonymous visitor · customer/guest on the public join link (signed out).

## Summary

**Runs (1 November 2026).**

1. Final full run of all 11 scenarios on a freshly created and seeded database: **110 / 113 PASS, 3 FAIL**. The three failures were test-harness problems, not product defects, confirmed from the screenshots: AUTH-01 — Edge failed to start (`browserType.launch`) while the machine was heavily loaded by other builds; SET-04 and SET-06 — the test clicked the next button while the previous dialog was still animating out (its backdrop swallowed the click; the data had been saved correctly).
2. Test fix: retry once on browser start; wait until no dialog is open before the next click (`lib/browser.mjs` `launch`, `dialogsClosed`). Scenarios 01 and 06 were then re-run on the restored seeded database: **29 / 29 PASS**.
3. Merged result (full run + re-runs, `tests/e2e/scripts/merge-reruns.mjs`): **113 / 113 PASS**. Rows that were re-run keep the original full-run failure text in "Actual result".

Earlier runs during the day found the product defects D1–D9 below; every one of those cases passes after its fix. An earlier full run was also invalidated by a pause of several hours (all sessions expired mid-run) and is not counted.
